# Architecture overview

The `src/sap_agent` package separates terminal orchestration, provider adapters, tools, SAP HTTP access, security, and audit output. The CLI loads the file based system prompt and settings, creates an allow-listed registry, then sends the question and read-only tool schemas to the selected LLM. Every requested tool passes policy checks before execution. In demo mode, the OData client returns fixed synthetic records without sending a request. In real mode, it issues OData v2 GET requests only. Tool results return to the LLM; each tool call is recorded in append-only JSONL with redacted arguments. Currency calculations use Decimal and keep currencies separate.

## SAP GUI bridge

GUI access is isolated behind `GuiBridge`. Validated YAML profiles under `config/transactions/` describe transaction fields, tiers, execute keys, result grids, and row caps. The generic runner observes the current screen, refuses to replace a different open transaction, resolves all requested fields before filling, then reads each field back. Filling a selection does not execute the report; execution requires a separate affirmative confirmation after value verification; the screen is reobserved and reverified before execution. Progress records phase status and duration without field values. Profile action plans are prevalidated and checked again immediately before each bridge action. Display and report tiers use row and session-step caps; write tier requests require action-specific approval and default to deny. The default `fake` bridge uses in-memory synthetic data only. The Java bridge remains disabled: the sanitized SAP GUI for Java recording and verified macOS access to the live process are missing, so this repository does not claim live SAP control.
