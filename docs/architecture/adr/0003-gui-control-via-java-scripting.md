# ADR 0003: Control SAP GUI for Java via scripting

- Status: proposed - safe fill/verify orchestration implemented; Java bridge pending sanitized recording and verified macOS access
- Context: Some SAP workflows are available through SAP GUI for Java rather than the current OData read tools. GUI control must remain behind a stable interface, use current-screen snapshots, and pass through policy and audit checks. SAP's Java client contains a built-in JavaScript scripting engine accessed through its Scripts menu; no sanitized recorded VA05 interaction was supplied to this project. The current host also denies process enumeration and System Events access, so its live accessibility tree cannot be verified here.
- Decision: Define `GuiBridge` with `observe`, `find_field`, and snapshot-bound `act` methods. Store transaction definitions as schema-validated YAML profiles and use one generic runner, search tool, and run tool rather than per-transaction Python recipes. The runner now observes before navigation, refuses to replace a different current transaction, pre-resolves fields, reads filled values back, and separates fill-only from explicit report execution. The entire action plan is prevalidated and each action is checked again immediately before dispatch. Display and report profiles use allow-list, row, action, and session-step caps; write profiles require approval and default to deny. Use an in-memory fake implementation for tests and development. Keep the default backend `fake` and do not enable `gui.bridge=java` until the sanitized recording and the actual Java scripting invocation path are reviewed and smoke-tested with a non-destructive report. Audit actions without field values.
- Consequences: The fake bridge supports profile, policy, audit, and agent-flow tests without starting or controlling SAP GUI. Adding a transaction requires a schema-valid profile, policy allow-list entry, and fake/runner tests; transaction-specific behavior does not belong in Python code. Live Java control remains unavailable; enabling it requires the sanitized script, confirmation that SAP GUI scripting is enabled in Preferences, and macOS Accessibility/Automation permission for the terminal process. No SAP save/post/delete action is implemented.
