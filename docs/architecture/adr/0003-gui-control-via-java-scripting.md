# ADR 0003: Control SAP GUI for Java via scripting

- Status: generic profile runner + bridge; java bridge pending recorded script
- Context: Some SAP workflows are available through SAP GUI for Java rather than the current OData read tools. GUI control must remain behind a stable interface, use current-screen snapshots, and pass through policy and audit checks. No recorded VA05 script has been supplied yet.
- Decision: Define `GuiBridge` with `observe`, `find_field`, and snapshot-bound `act` methods. Store transaction definitions as schema-validated YAML profiles and use one generic runner, search tool, and run tool rather than per-transaction Python recipes. Display and report profiles run under allow-list, row, and session-step caps; write profiles require approval and default to deny. Use an in-memory fake implementation for tests and development, and keep `JavaScriptBridge` as a `NotImplementedError` stub until a sanitized SAP GUI for Java recording is reviewed. Select the implementation through `gui.bridge`, defaulting to `fake`. Audit each action without recording field values.
- Consequences: The fake bridge supports profile, policy, audit, and agent-flow tests without starting or controlling SAP GUI. Adding a transaction requires a schema-valid profile, policy allow-list entry, and fake/runner tests; transaction-specific behavior does not belong in Python code. The Java implementation remains unavailable until the recorded script is reviewed and implemented.
